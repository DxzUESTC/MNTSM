# 数据迁移指南

当需要将模型迁移到新机器运行时，本文档说明需要移动哪些数据文件。

## 数据目录结构说明

项目中的数据主要分为以下几类：

### **必需数据**（训练时直接使用，必须移动）

这些数据是训练时直接读取的，**必须完整迁移**：

1. **`data/clips/`** - 对齐后的clip帧图片
   - 训练时直接读取这些图片作为输入
   - 体积：**最大**（包含所有对齐后的帧图像）
   - 路径示例：`data/clips/FFPP/deepfakes/c23/videos/clip_000/*.jpg`

2. **`data/dataset_index.pkl`** - 数据集索引文件
   - 包含所有clip的元信息（路径、标签等）
   - 体积：**小**（通常几MB到几十MB）
   - 训练时用于加载数据集

3. **`data/datasets/`** - 单独数据集索引（如果使用了）
   - `FFPP_index.pkl`、`FFPP_stats.json`
   - `Celeb-DF-v2_index.pkl`、`Celeb-DF-v2_stats.json`
   - 体积：**小**

4. **`data/splits/`** - 数据集划分缓存文件
   - `FFPP_split_42.pkl`（基于seed=42的train/val/test划分）
   - 体积：**很小**（几KB到几MB）
   - 如果重新生成会导致划分结果不同（即使seed相同，由于文件系统顺序等因素）

### **可选数据**（可重新生成，但移动可节省时间）

这些数据可以重新生成，但迁移可以节省预处理时间：

1. **`data/meta/`** - clip元数据JSON文件
   - 每个视频对应一个`clip_meta.json`
   - 体积：**中等**
   - 用于重建索引文件，如果不迁移需要重新预处理

2. **`data/faces_aligned/`** - 人脸对齐结果缓存
   - 已对齐的人脸图像（112x112）
   - 体积：**大**（比clips稍小）
   - 如果只修改`clip_len`或`stride`重新生成clips，可直接从缓存读取

3. **`data/features/`** - 特征向量缓存（.npy文件）
   - 用于关键帧选择
   - 体积：**中等**
   - 如果不迁移，需要重新计算特征

4. **`data/frames/`** - 原始抽帧结果
   - 从视频中抽取的原始帧
   - 体积：**大**
   - 如果不迁移，需要重新从视频抽帧

### **不需要移动**

1. **`data/raw_videos/`** - 原始视频文件
   - 如果新机器上已有原始视频，不需要移动
   - 体积：**非常大**（通常几十GB到几百GB）
   - 如果有原始视频，可以重新预处理生成上述所有数据

2. **`InsightErrorLog/`** - 错误日志
   - 仅为调试用，不需要迁移

## 迁移方案

### 方案一：最小迁移（仅必需数据）

**适用场景**：新机器上已有原始视频，或只需运行训练/评估

**需要移动**：
```bash
data/
├── clips/              # 必需（最大）
├── dataset_index.pkl   # 必需（小）
├── datasets/           # 必需（如果使用）（小）
└── splits/             # 必需（小）
```

**移动命令示例**（使用rsync，Linux/Mac）：
```bash
# 从旧机器到新机器
rsync -avz --progress \
  data/clips/ \
  user@new_machine:/path/to/project/data/clips/

rsync -avz --progress \
  data/dataset_index.pkl \
  data/datasets/ \
  data/splits/ \
  user@new_machine:/path/to/project/data/
```

**Windows PowerShell 示例**：
```powershell
# 使用 robocopy（Windows）
robocopy data\clips D:\target\data\clips /E /Z /R:3 /W:5
robocopy data\datasets D:\target\data\datasets /E /Z
robocopy data\splits D:\target\data\splits /E /Z
copy data\dataset_index.pkl D:\target\data\
```

### 方案二：完整迁移（包含缓存）

**适用场景**：需要在法机器上修改预处理参数或调试

**需要移动**：
```bash
data/
├── clips/              # 必需
├── dataset_index.pkl   # 必需
├── datasets/           # 必需
├── splits/             # 必需
├── meta/               # 可选（便于重建索引）
├── faces_aligned/      # 可选（避免重新对齐）
├── features/           # 可选（避免重新计算特征）
└── frames/             # 可选（避免重新抽帧）
```

### 方案三：从原始视频重新生成

**适用场景**：新机器上已有原始视频，有充足时间预处理

**步骤**：
1. 只迁移 `data/splits/`（如果需要保持相同的train/val/test划分）
2. 在新机器上从原始视频重新运行预处理流程
3. 参考 `src/preprocess/README_PREPROCESS.md`

## 迁移后检查清单

迁移完成后，在新机器上验证：

1. **检查索引文件是否存在**：
   ```python
   import pickle
   with open('data/dataset_index.pkl', 'rb') as f:
       dataset = pickle.load(f)
   print(f"总clips数: {dataset['num_clips']}")
   ```

2. **检查clip目录结构**：
   ```bash
   # 检查是否有clip图像文件
   ls data/clips/FFPP/deepfakes/c23/videos/clip_000/*.jpg
   ```

3. **运行小规模测试**：
   ```python
   # 尝试加载一个batch
   from src.train.dataset_loader import DeepfakeDataset
   import pickle
   
   with open('data/dataset_index.pkl', 'rb') as f:
       dataset = pickle.load(f)
   
   # 只加载前10个clips做测试
   train_dataset = DeepfakeDataset(dataset['clips'][:10], data_root='data')
   print(f"测试数据集大小: {len(train_dataset)}")
   sample = train_dataset[0]
   print(f"样本形状: {sample[0].shape}")  # 应该是 (C, T, H, W)
   ```

4. **检查配置文件路径**：
   - 确认 `configs/train_config.yml` 中的 `data_root`、`index_path`、`split_cache_path` 路径正确
   - 如果新机器路径不同，需要修改配置文件或使用相对路径

## 🔧 路径配置调整

如果新机器上的项目路径不同，需要调整配置文件：

**`configs/train_config.yml` 或 `ablation/baseline/config/train_config.yml`**：
```yaml
# 数据
data_root: data                    # 相对路径或绝对路径
index_path: data/dataset_index.pkl # 相对于项目根目录或绝对路径
split_cache_path: data/splits/FFPP_split_42.pkl
```

如果使用绝对路径，确保路径在新机器上存在且可访问。

## 优化建议

1. **压缩传输**：如果网络较慢，可以先用压缩工具打包：
   ```bash
   # Linux/Mac
   tar -czf data_clips.tar.gz data/clips/
   
   # Windows
   # 使用 7-Zip 或 WinRAR 压缩 data/clips 目录
   ```

2. **分批迁移**：如果数据量很大，可以按数据集分批迁移：
   ```bash
   # 先迁移 FFPP
   rsync -avz data/clips/FFPP/ new_machine:/path/to/data/clips/FFPP/
   # 再迁移 Celeb-DF-v2（如果需要）
   rsync -avz data/clips/Celeb-DF-v2/ new_machine:/path/to/data/clips/Celeb-DF-v2/
   ```

3. **使用外部存储**：如果两台机器在同一局域网，可以考虑使用共享存储（NAS/网络驱动器）

## 常见问题

**Q: 迁移后索引文件中的路径是否还正确？**  
A: 如果使用相对路径（如 `clips/FFPP/...`），只要保持 `data/` 目录结构不变即可。如果索引中使用了绝对路径，可能需要重新生成索引。

**Q: 是否可以只迁移部分数据集（如只迁移FFPP）？**  
A: 可以。如果配置文件设置了 `dataset_name: FFPP`，只需要迁移 `data/clips/FFPP/` 和对应的索引文件。

**Q: 如何验证迁移是否成功？**  
A: 运行训练脚本，如果能正常加载数据并开始训练，说明迁移成功。也可以先用上面的检查清单验证。

**Q: 迁移后需要重新训练吗？**  
A: 不需要。只要数据路径和结构保持一致，可以直接使用之前训练的checkpoint继续训练或评估。
